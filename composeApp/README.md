# Bridge client (`:composeApp`)

One Compose Multiplatform module builds three apps from the same code:

| Target | Entry point | Host |
|---|---|---|
| Web (Kotlin/Wasm) | `src/wasmJsMain/.../main.kt` | Static site: `index.html`, a service worker and a print stylesheet |
| Android | `src/androidMain/.../MainActivity.kt` | Native Activity, edge-to-edge |
| iOS | `src/iosMain/.../MainViewController.kt` | SwiftUI app in `/iosApp` (generated by xcodegen) |

The screens, matching and safety rules all live in `commonMain`, which is how Android and iOS stay
at feature parity. Compose renders natively on both, and its semantics map to TalkBack and VoiceOver.

## Run it

Needs JDK 21, Google Chrome for the web tests, the Android SDK (API 35), and Xcode for iOS.

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)    # or your JDK 21 path
./gradlew :composeApp:wasmJsBrowserDevelopmentRun   # web dev server
./gradlew :composeApp:installDebug                  # Android, onto a running emulator/device
open iosApp/iosApp.xcodeproj                        # iOS: run the iosApp scheme
./gradlew :composeApp:wasmJsBrowserTest :composeApp:testDebugUnitTest :composeApp:iosSimulatorArm64Test
```

Notes:
- **iOS project:** generated from `iosApp/project.yml`. Its build phase runs
  `:composeApp:embedAndSignAppleFrameworkForXcode` and finds JDK 17–25 on its own, because Xcode doesn't inherit your shell's `JAVA_HOME`.
- **Node:** add `-Pbridge.systemNode=true` to web tasks to use your installed Node instead of downloading one.

## Offline first, on every platform

| | Web | Android | iOS |
|---|---|---|---|
| Records built in | Seed file, precached by `sw.js` | Seed file in the APK | Seed file in the app bundle |
| Latest records from Supabase | `localStorage` | SharedPreferences | NSUserDefaults |
| App shell | Service worker | Installed | Installed |
| Provider websites | New browser tab | In-app WebView when online | In-app WKWebView when online |

The seed file is a Compose resource (`src/commonMain/composeResources/files/oc-resources.seed.json`,
the event's MIT-licensed data), read through `Res.readBytes` on every platform.
`tools/generate-seed-sql.py` reads the same file.

Bundle loading (`domain/BundleRepository.kt`): **backend → last saved copy → built-in seed.** When
running from the saved copy, the app shows "Working offline". It quietly picks up fresh records as
soon as the device reconnects.

**Third-party pages** (provider websites, source links) are the only part that needs the internet.
On mobile they open in `WebPageScreen`:
- **Online:** the page loads in the platform WebView, with Bridge's Back button and crisis bar still on screen.
- **Offline, or if the page fails:** a plain "Internet connection required" screen, with the address
  written out and a Try again button.
- **Inside the WebView:** only http(s) navigation is allowed. `tel:`, `mailto:` and app links are
  blocked, so a website can never call anyone or open another app.

Phone calls stay native (system dialer, after confirmation) because they don't need data.

## How it talks to the backend

| Call | When | If it fails |
|---|---|---|
| `GET /api/bundle` | Once at startup, and again on reconnect while offline | Uses the saved copy, then the built-in seed |
| `POST /api/intake` | Only when the user types free text | After 3s, silently asks the user to tap a need tile |

The backend URL is `DEFAULT_API_BASE_URL` in `Platform.kt`. Only the web build can override it,
with `?api=https://...`, or `?api=off` to use the seed file alone.

**Intake routes:**
- `danger`: hotline and staff, and every address stays hidden until Start over.
- `clinical`: "ask your care team", with no advice.
- `unknown`: an explicit no-match.

**Constraints** are flat slugs (`no-phone`, `phone-hard`).

## Safety rules enforced in the client

- **Locked door:** `referral_required` or `how_to_access: referral-only` means the next step is getting a
  referral. An address is only a destination for `walk-in`.
- **Address withholding:** a survivor-serving or confidential program's address is never rendered. That
  covers `addressWithheld`, `survivors`/DV tags, and DV populations.
- **Call buttons:** built only from numbers literally present in the `phone` text.
- **Honest uncertainty:** `medium`/`low` confidence gets a plain caveat. The source quote, link, date and
  notes are one tap away, and availability always reads "not confirmed".

Tests: `src/commonTest/kotlin/org/bridge/app/SafetyRulesTest.kt`. They run on web, Android and iOS.

## Platform code

Everything platform-specific sits behind a small `expect` API:

- **`Platform.kt`:** `configuredApiBaseUrl`, `readCache`/`writeCache`, `printHtml`, `hasInAppBrowser`.
- **`ui/PlatformUi.kt`:** `rememberIsOnline`, `InAppBrowser` and `PlatformBackHandler`.

| | Web | Android | iOS |
|---|---|---|---|
| Storage | `localStorage` | SharedPreferences | NSUserDefaults |
| Connectivity | n/a | `ConnectivityManager` | `NWPathMonitor` |
| Web pages | New tab | `WebView` | `WKWebView` |
| Print | `window.print()` | `PrintManager` | `UIPrintInteractionController` |
| Back | Browser | Back gesture | On-screen Back |

## Layout

```
src/commonMain/kotlin/org/bridge/app/
  App.kt                 screen routing
  Platform.kt            expect API + backend URL
  api/                   DTOs (seed schema), HTTP client, phone/link safety
  domain/                access rules (locked door, DV withholding), offline matcher, bundle loading
  i18n/                  EN/ES copy, 16 need labels
  ui/state/AppState.kt   screen stack and answers (in memory only)
  ui/screens/            one file per screen, including WebPageScreen
  ui/components/         resource card, crisis bar, focus-ring buttons
  ui/PrintCard.kt        printable card HTML (+ standalone document for native print)
src/commonMain/composeResources/files/   built-in seed file
src/wasmJsMain/          web entry, index.html (print CSS), sw.js
src/androidMain/         MainActivity, manifest, icon, Android actuals
src/iosMain/             MainViewController, iOS actuals
../iosApp/               SwiftUI host app (project.yml + generated .xcodeproj)
```
